## Retry Queue

- storage: `_didar_sync_state` post meta for submissions; `_didar_person_sync_state` user meta for Person sync.
- worker: per-item `didar_process_sync` and `didar_process_user_sync` WP-Cron hooks, plus recurring five-minute no-argument sweeps.
- lock: `didar_submission_sync_lock_<submission_id>` option with a 120-second TTL.
- historical attempt policy at the time of this QA: pending failures incremented `attempts` and retried below 10. This was superseded by the generation-scoped three-total-automatic-execution cap in `2026-09-14-sync-generation-retry-cap.md`.
- success cleanup: submission state becomes `synced`; user retry events are cleared. A completed submission had no pending per-item event after the worker callback.
- failure retention: pending state, last error, trace, attempt count, and failure event remain available for diagnostics.

## Bugs Found

### BUG-01 — Unsupported events pollute the seen-webhook ledger

- severity: Low
- reproduction: Send a validly authenticated Case payload with a unique `meta.id`.
- expected: Return 422 without adding an unsupported event to deduplication state.
- actual: The handler records `meta.id` in `didar_seen_webhooks` before validating the supported entity/action, then returns 422.
- evidence: Local runtime test observed the unique unsupported event ID in the ledger; the ledger was restored afterward.
- likely code area: `includes/class-didar-sync-manager.php`, `receive_webhook()` ordering around `seen_webhook()` and `webhook_event_key()`.

### BUG-02 — Non-array Deal `Fields` are acknowledged instead of rejected

- severity: Low
- reproduction: Send a validly authenticated Deal update whose `data.Fields` value is a string.
- expected: Clear 400 malformed-payload response with no queue or mutation.
- actual: The handler returns 200 and treats the malformed field container as empty. No business mutation occurred in the test.
- evidence: Local runtime test returned 200 for non-array `data.Fields`.
- likely code area: `includes/class-didar-sync-manager.php`, webhook payload validation before `update_local_from_deal()`.

No bugs were fixed during this QA pass, as required.
